# 구름고래의 작은 섬: 구현 계획

## 실행 개요

프로젝트 초기 설정은 실행 시 먼저 준비한다. Unity LTS와 C#으로 3D 쿼터뷰 WebGL 프로젝트를 만들고, Unity 테스트 도구와 정적 WebGL 배포 구성을 확정한다. 이후 게임 상태와 저장을 기반으로 장면을 만들고, 방치·건설·미니게임을 연결한 뒤 이야기·장식·공개용 화면을 통합한다.

## T1 — 게임 상태, 진행 규칙, 브라우저 저장

**목표.** 자원, 시설, 이야기, 장식, 엔딩을 단일 게임 상태로 관리하고 저장·복구한다.

**작업 대상.** 게임 상태·규칙·저장 모듈과 그 테스트 파일.

**행동 계약.** 네 기본 자원과 별빛 부품이 음수가 되지 않게 한다. 시설은 정해진 순서와 세 단계를 지키며, 재료가 부족하거나 이전 시설이 완성되지 않으면 변하지 않는다. 상태 변경 후 저장하고, 저장된 상태는 같은 화면으로 복구한다. 저장 불가 상황은 데이터 손실을 숨기지 않는다.

**검증.** 자원 소비, 순차 해금, 단계 전환, 엔딩 가능 조건, 저장·복구·초기화의 단위 테스트가 성공한다.

**판단 근거.** 방치·건설·이야기·장식이 같은 진행 상태를 공유하므로 먼저 안정적인 상태 경계를 만든다.

## T2 — 쿼터뷰 섬과 화면 골격

**목표.** 고래 섬과 고정 시설·장식 자리를 입체적으로 보이는 3D 쿼터뷰 화면으로 표시한다.

**작업 대상.** 게임 장면, 화면 구성, 자원 표시, 시설 자리, 스타일·에셋 정의 파일.

**행동 계약.** 네 시설 자리와 장식 자리가 화면에 일관된 위치로 보인다. 시설 단계와 장식 상태에 따라 3D 모델과 질감이 바뀐다. 고정 쿼터뷰 카메라, 조명, 그림자로 깊이를 표현한다. 사용자가 현재 자원과 다음 행동을 알아볼 수 있다.

**검증.** 개발 화면에서 초기 상태와 각 시설 단계, 장식이 렌더링되는지 확인하고 화면 구성 관련 테스트 또는 렌더링 점검을 실행한다.

**공유 파일 지침.** 상태 규칙과 저장 모듈은 T1만 수정한다. T2는 상태의 공개된 읽기 경계만 사용한다.

## T3 — 방치 수집, 건설, 미니게임, 엔딩 흐름

**목표.** 플레이어가 방치로 자원을 얻고, 희귀 발견과 미니게임·건설을 거쳐 엔딩까지 진행하게 한다.

**작업 대상.** 시간 흐름, 자원 발견, 미니게임, 건설 조작, 엔딩 화면과 관련 테스트 파일.

**행동 계약.** 기본 자원은 자동으로 늘고, 희귀 발견은 짧은 무벌점 미니게임으로 보너스 자원을 준다. 건설 버튼은 T1 규칙을 우회하지 않는다. 별 관측소 완성 시 엔딩을 한 번 보이고, 이후에도 장식 가능한 상태를 유지한다.

**검증.** 시간 경과 자원 증가, 미니게임 성공·시간 종료 보상, 부족 자원 거부, 네 시설 완성 후 엔딩, 엔딩 뒤 계속 플레이의 자동 테스트와 브라우저 수동 점검이 성공한다.

**공유 파일 지침.** T2의 장면 진입점에 직접 기능을 덧붙이지 않고, 행동·화면 연결 지점은 실행 단계의 단일 연결 작업에서 추가한다.

## T4 — 이야기 기록, 장식 카탈로그, 설정

**목표.** 건물 완성 이야기를 기록하고, 엔딩 뒤 장식과 저장 안내·초기화를 제공한다.

**작업 대상.** 이야기 생성·기록, 장식 카탈로그·배치, 기록첩·설정 화면과 관련 테스트 파일.

**행동 계약.** 시설 완성 시 하나의 짧은 이야기가 열리고 다시 읽을 수 있다. 장식은 엔딩 뒤 정해진 자리에만 놓이며 게임 능력치를 바꾸지 않는다. 장식 목록을 데이터로 추가할 수 있다. 저장 위치·한계와 초기화 결과를 사용자에게 분명히 보인다.

**검증.** 시설 완료별 이야기 기록, 기록 재열람, 엔딩 전 장식 제한, 장식 배치, 초기화 확인 흐름의 자동 테스트가 성공한다.

**공유 파일 지침.** T1의 상태 모듈을 확장해야 하면 T1이 제공한 공개 상태 경계만 사용한다. T3와 공통 화면 진입점은 실행 단계에서 한 번에 연결한다.

## T5 — 통합, 공개 화면, 품질 점검

**목표.** 모든 기능을 하나의 플레이 흐름으로 연결하고, 포트폴리오 공개에 필요한 안내와 품질을 마무리한다.

**작업 대상.** 애플리케이션 연결 지점, 공개용 안내·크레딧, 배포 설정, 전체 흐름 점검 파일.

**행동 계약.** 새 방문자가 게임을 시작해 엔딩과 장식까지 진행할 수 있다. AI 생성 이미지 사용 시 크레딧을 볼 수 있다. 로그인·온라인 기능이 없음을 저장 안내와 공개 화면에서 오해 없이 전달한다. 정적 배포 결과는 직접 열 수 있다.

**검증.** 전체 자동 검사와 생산 빌드가 성공한다. 새 게임 → 네 시설 완성 → 엔딩 → 장식 → 새로고침 후 이어하기의 수동 점검을 한다.

## 단계 간 연결

- T1이 모든 진행 상태와 저장 경계를 제공한다.
- T2는 T1 상태를 시각화한다.
- T3는 T1 규칙과 T2 화면을 사용해 핵심 플레이를 만든다.
- T4는 T1 상태와 T2 화면을 사용해 기록·장식·설정을 만든다.
- T5는 T3와 T4를 공통 진입점에 연결하고 공개 준비를 마친다.

```yaml
tasks:
  - id: T1
    depends: []
    risk: RISKY
  - id: T2
    depends: [T1]
    risk: MECHANICAL
  - id: T3
    depends: [T1, T2]
    risk: RISKY
  - id: T4
    depends: [T1, T2]
    risk: RISKY
  - id: T5
    depends: [T3, T4]
    risk: MECHANICAL
regen_barriers: []
```
